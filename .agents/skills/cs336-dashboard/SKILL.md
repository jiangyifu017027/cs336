# CS336 核心进度展示

## 定位

只展示两样东西，其他一律不展示（不列全表、不统计各档位数量、不列最近会话）：

1. **核心知识点链**——整门课的知识骨架，每个模块只取"核心步骤"；
2. **作业核心逻辑链**——作业的关键步骤流水线，走到哪、卡在哪。

- **只读**：不修改任何文件。更新进度 → `cs336-review`；讲解概念 → `cs336-study`。
- **不主动提问、不做理解检查**。
- **数据以文件为准**：每次展示前重新读档案，不凭记忆。

## 数据来源与"核心"的判断标准

读 `../../../learning/knowledge-map.md`（唯一进度表）和 `../../../learning/progress.md`（当前位置）。

- **核心知识点** = knowledge-map 各模块中加粗（`**…**`）的条目 + 每个模块"本模块重点"段落点名的主线。非重点条目不单独展示。
- **作业核心步骤** = A1 的依赖链（knowledge-map 的 A1-1～12，按其"本模块重点"描述分为 tokenizer → 模型 → 训练 三段；A3 一行带过）。

## 展示格式

整体控制在 20 行以内。用 ▶ 标出当前位置。

### 1. 核心知识点链

按学习顺序排成一条链，每个模块一行：模块名 + 核心条目（带编号）+ 状态。

状态取核心条目的"讲解/掌握"列合并判断：
- 核心条目全部 ✅ 讲解但掌握全 ⬜ → `已讲，待自评`
- 部分讲解 → `讲了 x/y`
- 未讲 → `未开始`
- 用户已自评 → 显示最弱一档（如 `最低 🟡`），因为短板决定下一步

示例（格式示意，数字以实际文件为准）：

```
主线（目标 🔵）：
A 分词     byte/char 区别 L01-5/6 · 压缩率 L01-8 · BPE 训练 L01-9      ▶ 已讲，待自评
B 两笔账   tensor 基础 L02-1 · 显存四件套 L02-2 · 精度 L02-3 · FLOPs L02-4/5   未开始
C 标准配方 骨架 L03-1 · SwiGLU L03-2 · RMSNorm L03-3 · RoPE L03-4 · attention 变体 L03-5   未开始

概念线（目标 🟢）：
D roofline L05-3 · E 四种并行 L07-3/4/5/6 · F Chinchilla+isoflops L09-3/4
G prefill/decode+KV cache L10-1/2 · H 数据配比+加工链 L13-1/6 · I SFT→RLHF→DPO、GRPO L15-2~5、L16-2 · 策略梯度 L17-1/4
全部未开始

收官：跨讲主线 M1 显存账本 · M2 FLOPs/算术强度 · M3 效率-规模权衡 · M4 训练阶段演进（最后统一自评）
```

概念线模块多、每条目标只是"能解释"，可以合并成 2–3 行，不必逐模块一行。

### 2. 作业核心逻辑链

A1 按依赖关系分三段，每段一行：步骤链 + 完成数 + 卡点；当前步用 ▶ 标注。

示例：

```
A1（核心产出：自己训练的小 LM）
① tokenizer   Unicode 书面题 → train_bpe → encode/decode → 测试全过        0/6  ▶ 卡在 train_bpe
② 模型        基础模块 → attention/RoPE → 完整 LM（test_model）            0/3  等 L02/L03
③ 训练        训练组件 → 训练循环 → 全测试通过 + 实验记录                   0/3  未开始
A3（可选）    本地实验 → 拟合 scaling law → 外推分析                        0/3  主线后定
```

- 完成数与卡点以 knowledge-map 勾选和 progress.md"当前作业剩余题目"为准；两处不一致时如实指出，建议用 cs336-review 对齐。
- A2/A4/A5 不在计划内，不展示。

## 输出原则

- 结尾不提问；可附一句"要更新进度说一声，我用 cs336-review 记"。
- 用户想看细节时再展开具体条目编号，不在默认输出里铺开。
