# CS336 作业协作（2026-11-26 起：实现模式）

## 模式变更

用户是业余自学者（非 Stanford 注册学生、无成绩场景），2026-11-26 明确决定：放弃"AI 只当助教"模式，改为**用户口述核心思路 → AI 直接实现代码并运行验证**。各作业仓库 `AGENTS.md` 顶部有本地覆盖说明，全局约定见根 `AGENTS.md`"作业边界"。

仍然有效：

- 不搜索、不指向第三方 CS336 作业实现（避免搬别人的答案；按用户思路新写不受此限）。
- 学习记录写在作业目录外的 `learning/`，如实标注"AI 按用户思路实现"。
- AI 实现的代码**不作为** `learning/knowledge-map.md` 的用户掌握度证据。

当前计划范围（2026-11-25 轻量计划，勾选清单见 `learning/knowledge-map.md`）：A1 是唯一排期的实现作业；A2/A4/A5 不在计划内，A3 为可选轻量版。不主动建议进入计划外作业。

## 实现模式工作方式

1. **先读要求再动手**：实现前读 handout 对应章节、`tests/adapters.py` 等接口约定，按课程要求的公开接口写，不自造接口。
2. **以用户思路为准**：用户给核心思路/设计，AI 落地成代码。用户没说的细节按 handout 与讲义补全，交付时说明补全了哪些决定；不擅自把用户思路换成另一套设计而不说明。
3. **跑测试验证**：实现后运行对应公开测试（如 `uv run pytest tests/test_train_bpe.py -q`），如实报告通过/失败；失败则继续诊断修复，或向用户说明卡点。2026-11-26 起 AI 可直接运行作业命令与 shell。
4. **交付时解释**：用中文逐段说明实现做了什么、关键取舍，让用户能看懂并指挥下一步。不主动提问、不做理解检查、不要求复述。

## 保留的辅助模式

以下模式不变，按用户请求选择，不要每次输出整套模板。

### 1. 读题与剩余题目导航

用户说"作业里还要做哪些 / 帮我看看作业"时，直接读 handout 对应章节，输出**剩余题目清单**：

- 按 handout 顺序列出尚未完成的题号与名称；
- 每题标注：书面题/代码题、要求要点（输入/输出和约束）、对应公开测试；
- 需要的前置概念与对应讲义；
- 建议的做题顺序。

清单以 handout 原文为准，不替用户决定"这题可以跳过"。

### 2. 环境检查

优先参考 `../../../STATUS.md`，避免重复安装已可用的环境。需要命令时 AI 可直接运行（如 `./scripts/check_envs.sh`），并解释输出。

把失败分为环境、数据、依赖、starter 未实现和真实代码问题。`NotImplementedError` 在 starter 阶段通常是预期状态，不盲目修环境。

### 3. 报错诊断

用户贴报错时：先定位最可能原因（接口、shape、数值、序列化、性能还是环境），实现模式下直接修复并说明原因；用户要求自己改时，改为给诊断方向（观察哪些 shape/dtype/不变量、最小 toy input、对照实验）。

### 4. 分析测试输出

先把信息压缩为：

- 通过/失败/跳过数量；
- 首个最有信息量的失败；
- 失败类型；
- 下一步动作。

不要只看失败总数，也不要通过修改公开测试、snapshot 或适配器来"变绿"。完整 traceback 很长时聚焦最相关的用户代码帧和断言差异。

### 5. Review 用户代码

按优先级检查：正确性、边界条件、张量约定、数值稳定性、复杂度、可读性。每条反馈包含"位置/观察/为什么"。实现模式下可直接给出修改后的代码并解释。

## 收尾

总结证据而不是只说"好了"：哪些测试通过、还缺哪些验证、作业里还剩哪些题。把"作业剩余题目"同步到 `learning/progress.md` 的待办清单，并交给 `cs336-review` 的记录流程。**不追问用户是否理解、不要求复述方案**。
