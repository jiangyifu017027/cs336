# CS336 复盘与进度管理

## 档案位置

- `../../../learning/plan.md`：总体学习计划（个人时间约束、轻量路线、每周节奏模板；2026-11-25 重构，只保留主线 L01–L03 + A1 与概念线 L05/L07/L09/L10/L13/L15–L17）。开始一次学习时用它确认“今天该做什么”。
- `../../../learning/progress.md`：当前位置、讲次/作业状态和下一步。
- `../../../learning/questions.md`：未解决问题及状态。
- `../../../learning/vocabulary.md`：实际遇到的英文术语。
- `../../../learning/sessions/`：每次学习记录。
- `../../../learning/templates/session.md`：会话记录模板。
- `../../../STATUS.md`：只用于核对环境，不代表学习进度。

读取当前任务需要的文件即可，不要每次加载全部历史。

## 开始一次学习

1. 阅读当前进度和最近一次会话（如果存在）。
2. 用一句话说明“上次到哪里、证据是什么、遗留什么”。没有历史就明确从头开始。
3. **默认不出检查题、不问回忆题**：用户 2026-11-23 明确要求以纯讲解为主，掌握度由用户自评并在写作业时自我验证。只有用户主动说“考考我 / 出几道题 / 复习”时才进入问答模式。
4. 和用户确定本次唯一的主要目标及可接受时长；默认一个 25～45 分钟的小节。
5. 给出一个明确动作，然后进入 `cs336-study`、`cs336-english` 或 `cs336-assignment`，不要花大量时间做计划。

如果用户已有明确目标，尊重目标，不强制走完整仪式。

## 结束一次学习

**不要求用户复述**（2026-11-23 用户要求）。只记录本次**讲解覆盖了哪些知识点**，以及用户主动表达的疑问或判断。掌握度留空，由用户在 `learning/knowledge-map.md` 自行勾选，或在作业中自行验证后再回填。然后更新：

### 会话记录

在 `learning/sessions/YYYY-MM-DD-主题.md` 中记录：

- 日期、主题和实际用时（未知就写未记录）；
- 本次讲解覆盖的知识点（对应 `knowledge-map.md` 的条目编号）；
- AI 辅助摘要；
- 用户主动提出的问题或判断（没有就写“无”，不要编造）；
- 遇到的问题、报错和解决状态；
- 遗留问题；
- 下一次最小动作；
- 建议复习日期（可选，只给建议，不主动安排提问式复习）。

### 进度文件

- 当前定位必须具体，例如“第 1 讲：理解 token 与 byte 的关系”，不要只写“继续学习”。
- 讲次可分为“未开始 / 学习中 / 已初学和待复习 / 已掌握”，作业可分为“未开始 / 读题 / 实现中 / 验证中 / 已完成”。
- 逐条知识点的掌握度由用户维护 `learning/knowledge-map.md`（`⬜ 未学 / 🟡 有印象 / 🟢 能解释 / 🔵 能独立使用`）；AI 只维护“已讲解”标记，不替用户判掌握。
- 保留下一步唯一且可执行，避免堆十几个待办。

### 疑问与词汇

- 已解决问题标记答案摘要和日期；未解决问题保留，不擅自删除。
- 只添加本次实际遇到的英文术语，中文释义要符合上下文。
- 不在学习记录中写可粘贴的作业答案、代码或伪代码。

## 复习模式

仅在用户主动要求复习时使用（默认不触发）。优先使用主动回忆：

1. 先隐藏旧答案，提出少量问题。
2. 等用户回答后，指出正确部分与缺口。
3. 对错误概念换一个例子或要求解释原因。
4. 根据回答更新“待复习”状态，而不是仅按日期机械标记掌握。

可按 1、3、7、14、30 天安排复习；时间未知时只建议下一次，不生成庞大计划。错题应记录“错误原因类型”，例如概念混淆、公式符号、shape、边界条件、英文误读。

## 输出风格

默认给出简短的状态摘要和下一步，不重复粘贴整个档案。所有文件更新都应与实际对话一致；日期不明时使用系统日期，不编造学习时长或成果。
