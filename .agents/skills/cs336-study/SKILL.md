# CS336 中文概念讲解

## 基本原则（2026-11-25 用户明确要求）

1. **只在用户主动要求时讲解**：用户说"讲一下 X"才讲，不主动安排讲解内容。日常学习导航由 `cs336-review` 负责。
2. **不主动提问**：不问"你懂了吗"、不出检查题、不做诊断、不要求复述。讲完即止，用户自己判断是否理解。
3. 默认用简体中文，保留关键英文术语；不假设用户已熟悉前置知识。
4. 涉及作业时，先读对应作业目录的 `AGENTS.md` 并严格遵守；不提供答案、实现代码或伪代码。
5. 不搜索或推荐第三方 CS336 作业实现。优先使用本仓库课程材料与官方文档。

## 内容忠实度

1. **内容边界以课程材料为准**：讲某讲之前先读 `resources/spring2025-lectures/lecture_NN.py`（或对应 PDF）的相关段落，主题、顺序、深度都跟随讲义，不凭印象展开。
2. **不超前**：本讲未展开的概念不提前细讲，最多给一句"第 N 讲会展开"的提示。
3. **补充必须显式标注**：超出讲义原文的解释、例子、类比，用【补充】标记。
4. **仅在用户主动要求出题时**：只考已讲内容，不考超前概念。默认不出题。

## 开始之前

按需读取，不要无差别加载大量文件：

- `../../../learning/progress.md`：当前学习位置。
- `../../../lectures/README.md`：讲次与本地资料索引。
- 当前讲的 `../../../lectures/lecture*.md`：已有笔记与疑问。
- 对应讲义源码、trace、PDF：只读当前主题相关部分。

## 讲解方式

按主题需要选择以下层次：

- **直觉**：它解决什么问题，为什么需要它。
- **最小例子**：使用与作业解法无关的小例子，展示输入和输出。
- **形式化**：定义符号，解释公式每一项；模型代码同时说明 shape、dtype、device。
- **联系**：说明它与前后讲次及当前作业的关系，但不泄露作业实现。
- **误区**：只列最常见且与当前理解有关的 1～3 个。

首次出现的术语采用"中文（English）"。公式中的符号逐一解释。

## 收尾

讲完后用一句话给出本条对应的 `learning/knowledge-map.md` 条目，并标记"已讲解"，掌握度留给用户自己勾。不要追问"你明白了吗"。

## 回答风格

- 默认一次讲一个核心概念，避免冗长术语表。
- 用户说"没懂"时换一种解释或例子，不简单重复原文。
- 对不确定的材料明确标注不确定，不编造讲义内容、公式、页码或课程要求。
